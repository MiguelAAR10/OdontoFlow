# Handoff — ERP-AGENTICO-01 · B3 staff reads (chat, handoffs, activity feed, productivity)

## Summary
- Human-only staff reads in `app/messaging/` (agents/integrations get 403 via `require_human`, even with the
  code): `GET /conversations` (keyset `last_message_at DESC, id DESC`, filters `status`/`location_id`, contact
  name patient → lead → masked phone `+•••…123`, 80-char preview), `GET /conversations/{id}/messages`
  (oldest → newest, `text` null when redacted/expired, `media_reference` never returned), `GET /handoffs?status=`
  (oldest first; `claimed_by` = conversation assignee only while `claimed`), `POST /handoffs/{id}/claim`
  (UUIDv4 `Idempotency-Key`, `conversations.resume`, `FOR UPDATE`, audit `reception_handoff.claimed`, 409
  `HANDOFF_NOT_PENDING`). Hand-back reuses `/internal/conversations/{id}/resume`.
- `app/observability/` (new): `GET /activity` (`proposals.read`) = one SQL `UNION ALL` of audit rows, proposal
  audit rows (agent + appointment proposals, with `agent_key`/`location_id`) and `agent_runs`; `actor_kind`
  human|agent|integration|system with display name ("Sistema" fallback); summary from a closed Spanish template
  map, never from state JSON. `GET /metrics/productivity?from&to&location_id` (`audit.read`, ≤ 92 days, local
  dates): appointments completed/no_show/cancelled, charged/collected/outstanding net of reversals (PEN),
  proposals created/approved/declined/expired per agent (lazy expiry; reception declines from audit),
  collection reminders approved. Computed on the fly.
- Migration `0023_agent_runs_reception` (head `0023`): `agent_key` adds `reception`; `conversation_id` +
  `trigger_message_id` with composite FK into `messages(organization_id, conversation_id, id)`; reception rows
  must be `event` with both set. `sales_agent/api.py` writes one run per turn on every path (completed / failed
  with category / 503 `agent_unavailable` / `unexpected` re-raised); best effort, never changes the response.
  No audit row per turn. Telemetry counters (model/tool calls) dropped.
- Profiles: secretaria `+conversations.resume`; administrador `+audit.read` (productivity gate).
- Spec: `docs/superpowers/specs/2026-10-01-erp-b3.md`. OpenAPI regenerated (6 paths added, none removed).

## Merge danger / risks
- Head moves to `0023`: any parallel branch adding `0023_*` must renumber.
- Claim replay returns the handoff's live state (a replay after resume shows `resolved` with
  `Idempotent-Replay: true`).
- After claim commits, `get_handoff` also requires `conversations.read`; a resume-only human gets 403 post-commit
  (not the demo profiles).
- Activity audit branch shows non-proposal actions (incl. IAM/credential action codes, no state) to anyone with
  `proposals.read`; consider an allowlist.
- 0023 composite FK is MATCH SIMPLE without a both-or-neither CHECK for non-reception rows.
- `entity_id::text` joins scan the org's audit rows per page (fine at demo scale); run row adds one synchronous
  transaction per turn. No test for two humans claiming simultaneously (covered by `FOR UPDATE`).
