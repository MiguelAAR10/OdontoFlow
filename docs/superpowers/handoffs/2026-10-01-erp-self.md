# Handoff — ERP-AGENTICO-01 · SELF patient self-booking + D-1 reminders

## Summary
- `POST /public/bookings` (`app/scheduling/public_booking.py`, existing scheduling router): the frontend BFF,
  using an integration credential with the new `patient-booking` profile (services/locations/practitioners/
  availability reads + `appointments.create`; integration-only via `INTEGRATION_ONLY_PROFILES`), books a
  **confirmed** appointment (L3, the patient confirms). Body `{service_id, location_id, practitioner_id?, start,
  full_name, phone(E.164)}`, `extra="forbid"`. A UUIDv4 `Idempotency-Key` per submit is required
  (`public_booking.create` receipt; replay → `Idempotent-Replay: true`). One transaction: past start → 422,
  per-phone advisory lock, lead resolved by contact identity → lead phone → new `direct` lead, rate limit 3 per
  phone per 24 h → 429 `PUBLIC_BOOKING_RATE_LIMITED`, membership/capability of a given practitioner (404/409),
  deterministic slot engine (off-grid/outside hours → 422, taken → 409 `SLOT_BLOCKED`). Non-integration
  callers → 403. Response: `reference` (`OF-<id>`) + interval. Audit `appointment.created` + domain event
  `appointment.booked_by_patient`.
- `POST /agent-runs {agent_key:"confirmaciones"}` (`app/agents_runtime/confirmaciones.py`): human-only
  (`appointments.read` + `deliveries.create`; agent/integration → 403). Kill switch
  `AGENT_CONFIRMACIONES_ENABLED`. One SQL picks tomorrow's confirmed appointments (location timezone) with their
  latest reachable conversation and queues one fixed-template reminder each (L1). Dedupe key
  `(org, appointment, start_utc)`. No conversation → `skipped`. Counts are stored in `agent_runs`.
- Migration `0024_agent_runs_confirmaciones` (head `0024`) widens `ck_agent_runs_agent_key`. The ORM mirrors it.
- Spec: `docs/superpowers/specs/2026-10-01-erp-self.md`. OpenAPI regenerated (additive).

## Merge danger / risks
- `reminder_key` hashes `start_utc.isoformat()` from a raw `text()` query, so the offset depends on the
  connection TimeZone. If it changes between runs, the reminder is duplicated. Fix: `.astimezone(UTC)`.
- The advisory lock is keyed on the submitted phone, but the count also matches the resolved lead. Two phones
  resolving to one lead can go one booking over the limit under a race. This only weakens a demo guard.
- The past check uses the app clock and the rate-limit window uses DB `now()`.
- Without OTP, lead reuse by phone lets an anonymous submitter attach an appointment to an existing lead, and the
  submitted `full_name` is ignored. A known privacy residual. Phone matching is exact E.164.
- The downgrade of 0024 DELETEs `confirmaciones` agent_runs rows (data loss on rollback, test-pinned).
- The `run_agent` docstring still says "agent only proposes". That is stale for confirmaciones.
- No test covers a 23P01 GiST loser on `/public/bookings`. Coverage is delegated to existing retry tests.
