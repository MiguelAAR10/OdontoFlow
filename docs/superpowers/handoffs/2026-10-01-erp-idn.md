# Handoff — ERP-AGENTICO-01 · IDN human identity per person + secretaria/administrador + GET /me

## Summary
- `scripts/issue_credential.py`: `--type human` is now issuable, but only with the human profiles `secretaria` and
  `administrador` (`HUMAN_PROFILE_PERMISSIONS`, explicit tuples). `profile_role()` gives the role code, name and
  permissions for a profile. Human roles are `staff-secretaria` / `staff-administrador`, and integration roles keep
  `integration-<profile>`. A type/profile mismatch, or `system`, exits 2 before any DB write. A `human` principal is
  never reused by name across organizations; integration/agent principals keep the old lookup.
- `secretaria`: agenda, patients, visits, the till (charges, payments, follow-ups), waitlist, `conversations.read`,
  and `contact_appointments.book` (approve appointment proposals). `administrador` adds products, movements,
  `reorder_points.manage` and `payments.reverse`. No new permission codes, no migration, and head stays `0020`.
- `app/iam/router.py`: `GET /me` (`Depends(require_authenticated_context)`, read-only) returns principal
  `{id, type, display_name}`, organization `{id, name}`, `roles [{code, name}]` for the credential's organization
  only (active membership), and the sorted `permissions`. It is mounted in `app/__init__.py` in the authenticated
  router loop.
- `scripts/seed_demo.py --issue-staff-credential` also issues Lucía Ramos (secretaria) and Carlos Vega (administrador).
  All credentials are created in one transaction and committed once. The script then writes `BACKEND_DEMO_HUMANS`
  (`[{role, display_name, token}]`) as line 2 of `.env.demo.local` (0600) in a single write. `reception-staff-demo`
  is unchanged. `issue_staff_credential(include_humans=False)` keeps the old one-line output.
- No change to `app/context.py`, `app/errors.py`, `app/db.py` or the migrations.

## Deviations
- Human role codes use a `staff-` prefix, so they never collide with tenant-created `secretaria` roles.
- The seed takes an `include_humans` flag instead of always writing line 2, which keeps `test_seed_demo.py` unchanged.
- The spec `docs/superpowers/specs/2026-10-01-erp-idn.md` is outside the listed write surface. It is accepted as this
  card's spec.

## Merge danger / risks
- `_assign_profile` has no type guard of its own. Only `cmd_issue` checks `profile_matches_type`. At runtime,
  `_require_human_principal` still blocks an agent from reversing.
- The human CLI prints its token once to stdout, which is the existing CLI contract. The seed never prints tokens.
  "Tokens never printed" holds for the seed and the API only.
- The OpenAPI for /me documents a 403 that can never happen (it comes from the shared security installer), and its
  401 text says "integration credential".
- `administrador` has no `consumptions.*`. Check with product if the admin shell shows consumptions.
- /me does not None-check `db.get(...)`. A stale ctx would give a 500 instead of an error envelope.
- The decline-proposal route is not tested with a human principal. It shares `_require_human_reviewer` with confirm.
- /me uses the read rate-limit budget, so the BFF should cache it per session.
