# Handoff — ERP-AGENTICO-01 · B5a early eval harness (AIRY Recepción, final DB state, pass^k)

## Summary
- New top-level package `evals/` (spec `docs/superpowers/specs/2026-10-01-erp-b5a.md`):
  - `harness.py` — `EvalDatabase`: on the `TEST_DATABASE_URL` server (127.0.0.1:5434) one throwaway template
    `odontoflow_eval_<pid>_<hex>` (`alembic upgrade head` + `seed_demo(anchor)` + `n8n-inbound` and
    `sales-agent-v0` credentials, minted with the `scripts/issue_credential.py` helpers); per trial a
    `CREATE DATABASE … TEMPLATE` clone + its own agent-memory DB; everything `DROP … WITH (FORCE)` in `finally`.
    `run_conversation` wires backend `create_app()` + Sales Agent `create_app(runtime=…)` + `SandboxInboundSender`
    in-process (`TestClient`), the same path as `tests/test_sandbox_inbound.py`. No second path into the agent.
  - `scenarios.py` — 5 Peruvian-Spanish scenarios (below); `given` hook links the contact to a seeded future
    appointment for reschedule/cancel.
  - `checks.py` — state-only checks; `GUARDS` run on every trial: md5 fingerprints of `charges`, `payments`,
    `payment_reversals`, `charge_follow_ups`, `inventory_movements`, `service_consumptions`, `products` unchanged;
    `agent_proposals` count unchanged (no L2/L4); `appointments` count unchanged. `resolve_conversation` finds the
    trial's conversation from its contact even when a turn crashed.
  - `fake_model.py` — deterministic offline receptionist policy (keyword intent → typed V0 tools →
    `SalesAgentResponse`); it never sees scenarios or checks.
  - `runner.py` — `run_suite` → `SuiteResult` (`passes`, `pass_k`, suite fraction, `exit_code`, report, baseline).
  - `__main__.py` — `python -m evals [--mode fake|real] [--k 3] [--scenario KEY] [--anchor-date]
    [--env-file PATH] [--write-baseline PATH] [--server-url URL]`; `main(argv, scenarios=None) -> int`.
    Real mode reads only model-provider keys (allowlist) from the env / `--env-file`; no key → exit 2
    `REAL_MODEL_UNAVAILABLE` before any database is created.
- Baselines: `evals/baselines/fake-pass3.json`, `evals/baselines/real-pass3.json`.

## Deviations
- Outside the B5a write surface (lead-approved): `alembic/env.py` (one line: `disable_existing_loggers=False`)
  and one regression test in `tests/test_migrations.py`. No migration revision changes; `app/`, `sales_agent/`,
  `integrations/`, `scripts/` untouched.
- The spec first said the booking conversation stays `open`; the domain sets `awaiting_confirmation` after a
  proposal (`app/agent_tools/booking.py:255`). Spec and check corrected.
- `evals/baselines/real-pass3.json` was written before the `resolve_conversation` fix; the fix only changes
  which checks a crashed trial lists, never whether it passes (a crashed turn always fails), so the recorded
  numbers stand. The real model was not re-run (one opt-in run only).
- `evals` is not in `pyproject.toml` `packages.find` (outside the write surface); run it from the repo root.

## Risks / limits
- V0 has no reschedule/cancel tool, so those scenarios expect a handoff; when the reception tools grow
  (B4), the expectation must move to "pending reschedule/cancellation proposal".
- The fake mode measures harness + tool boundary + backend contracts, not model quality; only the real
  mode measures the agent.
- Real-mode finding (not fixed, outside the surface): with `deepseek-v4-flash-0731` most turns end without a
  structured response. Unverified hypothesis: the model answers in plain text instead of calling the
  `SalesAgentResponse` tool of `ToolStrategy`; content is deliberately not logged, so confirming needs a
  model/strategy experiment in `sales_agent/`.
- The anchor defaults to today in Lima; scenario dates are relative to it (`evals/dates.py`).
- Each trial uses ~2 databases on the shared 5434 server (template cloning); concurrent pytest is still
  forbidden.
