# Handoff — ERP-AGENTICO-01 · COB collections agent (deterministic sweep + "run now")

## Summary
- Migration `0022_agent_runs` (head `0022`): table `agent_runs` (closed `agent_key`/`trigger`/`status` CHECKs,
  running ⇔ no `finished_at`, failed ⇔ `error_category`, completed ⇒ proposed+deduped+skipped = candidates,
  `triggered_by` composite FK into `memberships`). No new permission codes.
- `app/agents_runtime/` (new): `POST /agent-runs {agent_key:"cobranza"}` runs the sweep synchronously. One
  org-scoped SQL selects charges with a net-of-reversals balance > 0 and local age >= 7 days. A fixed Spanish
  template drafts the reminder (no LLM). Each candidate becomes at most one `collection_reminder` proposal
  (`agent_key='cobranza'`, dedupe `collection:charge:<id>:<date>`, evidence amount/balance/`days_since_issued`/
  last payment). Already proposed today → `deduped`; no reachable conversation or paid meanwhile → `skipped`;
  any other error fails the run (`error_category` = AppError code or `unexpected`). Audit + domain event per run.
  The agent never approves or executes. `GET /agent-runs?agent_key=&limit=` (`proposals.read`), newest first.
- tx1 order: claim receipt → permission check → kill switch → provisioning → insert run. A same-key replay
  returns the run as it is now (even `failed`) and never sweeps again.
- Kill switch `AGENT_COBRANZA_ENABLED=false` → 409 `AGENT_DISABLED` (`details.reason=disabled`). Human trigger
  without an active, permitted `airy-cobranza` member in the org → 409 `reason=not_provisioned`.
- `app/proposals/service.py`: `create_proposal` gains a server-only `agent_key` keyword (never from a body).
- `scripts/seed_demo.py`: sandbox conversation for the S/ 180 patient only + `airy-cobranza` agent principal
  (`collections-agent` profile, no credential).
- Spec: `docs/superpowers/specs/2026-10-01-erp-cob.md`. OpenAPI regenerated (2 additive routes).

## Merge danger / risks
- Human path checks the `airy-cobranza` membership and permission but not `Principal.is_active`: a deactivated
  agent principal can still be the proposer. Approval stays human, so no bypass.
- Only `sweep` is in the try/except: if `_complete` raises, the run stays `running` and no `agent_run.failed`
  audit row is written.
- ORM `__table_args__` omit four 0022 CHECKs (model drift only; DB enforces them).
- `proposed_today` dedupe is read outside `create_proposal`'s transaction; two concurrent same-day runs after
  a decline can both propose (B2's open-slot unique index still caps open proposals at one).
- Any agent/integration with `proposals.create` + `charges.read` can trigger; proposals are stamped
  `agent_key='cobranza'` regardless of caller identity.
- Seed contact-identity lookup matches `external_contact_id` only (demo edge case).
- `openapi.yaml` anchors renumbered by regeneration (no contract change).
