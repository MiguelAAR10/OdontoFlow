  `inventory_entry`) and `ck_agent_runs_agent_key` (+`inventario`). ORM CHECK mirrors widened too.
- `POST /agent-runs {agent_key:"inventario"}`: `run_agent` dispatches each key explicitly (inventario never hits

  decrements surplus in memory across the run. `target_fill = 2*min - balance` (`TARGET_MULTIPLIER`). Donor →
  `inventory_transfer` (qty `min(target_fill, surplus)`), none → `inventory_entry`.

## Merge danger / risks
- `normalize_payload` runs outside the sweep's try/except: an INVALID_INPUT there (e.g. quantity over
  max_digits) fails the run instead of counting as skipped.
- Second-target evidence shows the donor's original balance next to the in-run decremented surplus.
- Surplus promised to pending transfers from earlier runs is not reserved; competing items resolve via supersede.
- Candidate order (location, product) favors lower location id over worse shortfall when a donor is scarce.
- No `is_active` check at approve time for product/location (accepted by spec).
- `max(movement.id)` can miss a concurrent lower-id commit; `require_stock` under lock remains the floor.
- Open transfer + open entry on one subject prevented only by the sweep, not a DB invariant.
- `openapi.yaml` regenerated; merges touching `AgentKey`/`InboxKind` enums will conflict.
