## Telos
Fill the empty chair: when a confirmed appointment in the next 48h is cancelled, the secretaria's inbox shows "Cupo libre — ofrecer a 3 pacientes en lista de espera (cita #412)" with the evidence (Limpieza dental, mañana 10:00, Lince); she approves and those 3 patients receive the offer on WhatsApp (sandbox outbox).

## Hypothesis of value
The fact (`appointment.cancelled`), the demand (`waitlist_entries`), the channel (outbox) and the approval loop exist; missing are a durable, exactly-once-ish job runner and one matching query. No LLM: SQL matches, code ranks by `created_at`, a human approves the message.

## Observable metric
Test fixture (4 open reachable entries for the service/location/window): cancel tomorrow 10:00 → `run-due` → `enqueued=1, claimed=1, done=1`, one `waitlist_offer` with the 3 oldest `entry_ids`, evidence `matched=4`; approve as Lucía → 3 entries `offered`, 3 `outbound_messages`; second `run-due` → `enqueued=0, claimed=0`; re-approve → replay, still 3 messages.

## Contract
**Constants** — `app/agent_jobs/service.py`: `LEASE = 5 min`, `MAX_ATTEMPTS = 3`, `RETRY_DELAY = 60 s × attempts`, `BACKFILL_HORIZON = 48 h`, `RUN_DUE_DEFAULT_LIMIT = 10` (max 20), kill switch env `AGENT_BACKFILL_ENABLED` (default true), `BACKFILL_PROPOSER = "airy-backfill"`. `app/proposals/executors.py`: `OFFER_TTL = 30 min` (proposal TTL and the window stated in the message), `MAX_OFFER_ENTRIES = 3` (order `created_at, id`). `app/scheduling/waitlist.py`: `MAX_MATCH_CANDIDATES = 50`, `MORNING_END = 12:00` local.
**Migration 0026** (down 0025, new, additive): table `agent_jobs(id Identity, organization_id, agent_key, job_key, source_event_id NOT NULL, run_after, status, lease_token uuid NULL, leased_until NULL, attempts int default 0, last_error text NULL, created_at, updated_at)` — no payload column (the event payload holds `appointment_id`); widen `ck_agent_proposals_kind` + `waitlist_offer`, `ck_agent_runs_agent_key` + `backfill`. ORM mirrors in `app/agent_jobs/models.py`, `PROPOSAL_KINDS`/CHECK in `app/proposals/models.py`, CHECK in `app/agents_runtime/models.py`. Downgrade deletes `waitlist_offer`/`backfill` rows, drops the table, restores the 0025 sets.
**Enqueue** `enqueue_from_events(session, ctx)` (own tx): one `INSERT … SELECT … ON CONFLICT (organization_id, job_key) DO NOTHING` over **the caller's org** events `event_type='appointment.cancelled'`, `occurred_at ≥ now()−48h`, `(payload->>'start_utc')::timestamptz` in `(occurred_at, occurred_at+48h]` → `job_key='backfill:event:<id>'`, `agent_key='backfill'`, `source_event_id=id`, `run_after=now()`, `queued`. Returns rows inserted.
**Claim** `claim_one(session, org, enabled_keys)` in its own tx (`claim_in_tx` is the same without `begin`, used by the concurrency test): first `UPDATE agent_jobs SET status='dead', lease_token=NULL, leased_until=NULL, last_error=COALESCE(last_error,'lease_expired') WHERE organization_id=:org AND agent_key = ANY(:keys) AND status='leased' AND leased_until ≤ now() AND attempts ≥ MAX_ATTEMPTS` (scoped exactly like the claim; clears token+lease so the leased-iff-token CHECK holds); then `UPDATE agent_jobs SET status='leased', lease_token=gen_random_uuid(), leased_until=now()+LEASE, attempts=attempts+1, updated_at=now() WHERE id=(SELECT id … WHERE organization_id=:org AND agent_key = ANY(:keys) AND ((status IN ('queued','failed') AND run_after ≤ now()) OR (status='leased' AND leased_until ≤ now())) ORDER BY run_after, id LIMIT 1 FOR UPDATE SKIP LOCKED) RETURNING id, job_key, source_event_id, lease_token, attempts`. The kill switch is read before every claim: disabled keys are never claimed and stay `queued`.
**Settle** `settle(session, org, job_id, token, *, ok, error=None)` (own tx): `UPDATE … WHERE organization_id=:org AND id AND status='leased' AND lease_token=:token`; ok → `done`, else `failed` with `run_after=now()+RETRY_DELAY×attempts` or `dead` at `attempts ≥ MAX_ATTEMPTS`; token/lease cleared, `last_error` = `AppError.code` or `"unexpected"`. 0 rows → `LeaseLost` (the stale worker's outcome is discarded, counted `lost`).
**Tick** `run_due(session, ctx, limit)`: tx `_authorize(reads=(APPOINTMENTS_READ, WAITLIST_READ))` → `enqueue_from_events` → if the kill switch is on AND a due backfill job of the org exists (`has_due`, read-only), resolve the proposer **once, before any claim**: `_proposer(name="airy-backfill", agent_key="backfill")` → 409 `AGENT_DISABLED not_provisioned` leaves every job `queued` with `attempts` unchanged → loop up to `limit`: kill switch → `claim_one` → `backfill.start` + `backfill.process` → `settle` (`LeaseLost` → counted `lost`). JobOut `status` is the settle outcome `done|failed|dead|lost`.
**Handler** `app/agents_runtime/backfill.py`: `start(session, ctx=caller, job) -> run_id` (own tx) inserts `agent_runs(agent_key='backfill', trigger='event', status='running', triggered_by_principal_id=caller.principal_id)` (the run-due caller; `_complete`/`_fail` and the run audit use the caller's ctx, exactly like COB's manual runs); `process(session, run_id, job, caller, proposer)` calls `_propose` and settles the run (`_complete`, or `_fail` + re-raise so the tick settles the job `failed` with `last_error`=`AppError.code` or `"unexpected"`); `_propose` loads the event and the cancelled appointment (org-scoped). Skip (run `completed`, `skipped=1`) when: event/appointment missing, not cancelled, `start_utc ≤ now()+OFFER_TTL`, slot taken (`slot_is_free`: no `confirmed` appointment of that practitioner overlapping `[start,end)`, practitioner-global like the GiST). Dedupe (run `deduped=1`) when any `waitlist_offer` exists on subject `appointment:<id>` (any status). Run counts are per freed slot because `ck_agent_runs_counts` requires `proposed+deduped+skipped = candidates`: a proposed/deduped/skipped slot is `candidates=1`; no reachable match is all zeros; the number of matching entries is `evidence.matched`, never `candidates_count`. Matching: `matching_open_entries` (one SQL query in `waitlist.py`, `LIMIT MAX_MATCH_CANDIDATES`): org, `status='open'`, same `service_id`, `location_id` NULL or equal, `practitioner_id` NULL or equal, slot local date (location tz) in `[earliest_date, latest_date]`, `preferred_window IN ('any', morning|afternoon)` (morning = local start < 12:00), `lead_id ≠` the appointment's lead, `patient_id IS NOT NULL` (lead-only entries are not candidates), ordered `created_at, id`; then each candidate is filtered by **the one reachability helper** `reachable_conversation(session, org, patient_id)` (org, `consent_status <> 'opted_out'`, `Conversation.status <> 'closed'`). `matched` = reachable count (of at most `MAX_MATCH_CANDIDATES` read); first `MAX_OFFER_ENTRIES` are offered. None → run `candidates=0`. Else `create_proposal(kind='waitlist_offer', agent_key='backfill')`; `INVALID_INPUT`/`NOT_FOUND` → skipped; other errors → run `failed` (`_fail`) and re-raised → job `failed`.
**Kind `waitlist_offer`** (`executors.py`): args (`extra="forbid"`) `appointment_id:int>0, entry_ids: list[int>0] (1..3, unique), message_text: str (1..1000)`; `required_permission=DELIVERIES_CREATE`, TTL `OFFER_TTL`, subject `("appointment", str(appointment_id))`, `location_id`=appointment's, `conversation_id=None`, `revalidate` no-op. Version `"{free|taken}|{sorted ids of entry_ids still open}"` (`-` when the appointment is gone). Subject resolver requires the appointment cancelled, slot free and every entry open + matching (same `matching_open_entries(entry_ids=…)`), else `INVALID_INPUT`. Summary (args only, the callable gets no session): `"Cupo libre — ofrecer a {n} pacientes en lista de espera (cita #{appointment_id})"`; service, sede and time live in `evidence`. Text: `"Hola, se liberó un cupo de {servicio} el {dd/mm} a las {HH:MM} en {sede}. Responde SÍ en los próximos 30 minutos para reservarlo."`. Execute (as approver): `offer_waitlist_entries(session, ctx, entry_ids=, proposal_id=, appointment_id=)` in `waitlist.py` — one tx: `require_permission(waitlist.manage)`; appointment loaded org-scoped, must still be `cancelled` with the slot free (re-checked here, else `INVALID_INPUT`, nothing offered or sent); entries locked `WHERE organization_id = ctx.organization_id AND id = ANY(entry_ids)` ordered by id and re-checked with `matching_open_entries` (service, location, practitioner, date, window); each still matching + reachable → `offered` (others untouched), `record_event('waitlist_entry.offered')` + `record_domain_event('waitlist.offered', {entry_id, proposal_id, appointment_id, start_utc, offer_expires_at})` (event literal inlined in `waitlist.py`); none offered → `INVALID_INPUT`. Then per offered entry `enqueue_outbound_message(conversation_id, key=offer_message_key(execution_key, entry_id))` — a deterministic UUIDv4-shaped key (sha256 of `waitlist_offer:{execution_key}:{entry_id}`), because `outbound_messages.idempotency_key` is `varchar(36)` with a UUIDv4 CHECK; a retried execute hits the same message → `result_ref={type:"waitlist_offer", entry_ids:[…], outbound_ids:[…]}`.
**Approval permissions.** Approve checks `proposals.decide` + `deliveries.create` (403 otherwise). The executor also needs `waitlist.manage`; an approver holding `deliveries.create` without `waitlist.manage` gets the proposal `approved` then `failed` (`PERMISSION_DENIED`), 0 entries offered, 0 messages. Secretaria holds all three, so the demo path is unaffected.
**Route** `POST /agent-runs/jobs/run-due` (on the already-mounted `agent_runs_router`; no `app/__init__.py` change) body `JobsRunDue{limit:int=10 (1..20)}` (`extra="forbid"`), 200 `JobsRunOut{enqueued, claimed, done, failed, dead, lost, disabled_agents:list[str], jobs:[JobOut{id, job_key, agent_key, status, attempts, run_id|null, last_error|null}]}`. No `Idempotency-Key`: a tick is safe to repeat (unique `job_key`, leases). Org-scoped to the caller. Profile `backfill-agent=(proposals.create, proposals.read, appointments.read, waitlist.read)` in `issue_credential.py`. CLI `odontoflow jobs run-due [--limit N]` → that route (`OdontoflowApi.run_due_jobs`). Literals: `RunAgentKey` + `backfill` (also the `GET /agent-runs?agent_key=` filter type), `InboxKind` + `waitlist_offer`; `AgentKey` (POST /agent-runs) and `ProposalKindName` stay closed (→ 422).

## Invariants (PostgreSQL enforces)
- `UNIQUE(organization_id, job_key)` (one job per event); `UNIQUE(organization_id, id)`; composite FK `(organization_id, source_event_id)` → `domain_events(organization_id, id)` RESTRICT; org FK RESTRICT.
- CHECKs: `status IN ('queued','leased','done','failed','dead')`; `agent_key IN ('backfill')`; `attempts ≥ 0`; `(status='leased') = (lease_token IS NOT NULL AND leased_until IS NOT NULL)`. Partial index `(organization_id, run_after) WHERE status IN ('queued','failed','leased')`.
- Mutual exclusion: `FOR UPDATE SKIP LOCKED` claim; fencing: settle matches `lease_token`, a reclaimed job gets a new token.
- Closed CHECKs on `agent_proposals.kind`/`agent_runs.agent_key`; one open offer per appointment (`uq_agent_proposals_open_dedupe`); `waitlist_entries` status CHECK + composite tenant FKs; one message per `(org, idempotency_key)` in the outbox.
- Residual (accepted, not a DB claim): a stale worker's proposal creation is not fenced, only deduped; an outbox failure after `offered` leaves that entry offered without message (proposal `failed`); a booking landing between `offer_waitlist_entries` commit and the outbox enqueue still sends the offer (the SIM card's booking path re-checks the slot).

## Acceptance tests (written first; `tests/test_agent_jobs.py`, `tests/test_backfill.py`, `tests/test_migrations.py`; real PostgreSQL, one process)
1. Deterministic exclusion: thread A claims inside an open tx and signals; B claims while A's row lock is held → `None` over 1 job, the other id over 2 jobs; A commits.
2. Lease expiry: worker A claims, `leased_until` forced past → B reclaims (new token, attempts 2); A's settle → `LeaseLost`, row stays B's; B settles `done`. Expired with attempts 3 → `dead` with token and lease cleared; the dead-sweep never touches org B's or a disabled agent's rows.
3. Failure path: handler raises → `failed`, `run_after` pushed, `last_error` set, run `failed`; third failure → `dead`.
4. Kill switch off → `claimed=0`, `disabled_agents=["backfill"]`, job stays `queued`; on → next tick claims it.
5. Enqueue: same event scanned twice → 1 job; cancellation of an appointment 3 days out → no job; other `event_type` → no job; org-B tick never sees org-A events/jobs.
6. Demo: cancel tomorrow-10:00 Limpieza at Lince with 4 matching + 1 wrong-service + 1 wrong-window + 1 opted-out + 1 lead-only entries → one `waitlist_offer`, `entry_ids` = 3 oldest matching, evidence as the example (`matched=4`), `proposed_by`=`airy-backfill`, `agent_runs` row `backfill/event/completed` with `triggered_by`=caller; `GET /agent-runs?agent_key=backfill` lists it.
7. Re-run tick / re-enqueued event → no second job, no second proposal; after decline → still none.
8. Approve as Lucía → `executed`, 3 entries `offered`, 3 outbound messages, audit + `waitlist.offered` events; re-approve same key → replay, still 3.
9. Drift: slot rebooked or one entry cancelled before approval → 409 superseded, nothing sent; approver without `deliveries.create` → 403; approver with `deliveries.create` but without `waitlist.manage` → proposal `failed`, 0 offered, 0 messages; slot rebooked after tx1 (inside execute) → `failed`, 0 offered, 0 messages.
10. Gate: no reads → 403; `system` → 403; human trigger without `airy-backfill` → 409 `not_provisioned` and the job stays `queued` with `attempts=0`; body `{limit:0}` / extra field → 422; `POST /agent/proposals {kind:"waitlist_offer"}` → 422; CLI `jobs run-due` posts to the route (test in `tests/test_agent_jobs.py`).
11. Migration 0026 round-trip; CHECKs reject bad status/agent_key and a leased row without token.
